# Тестовое окружение проекта (`/tests`)

Директория предназначена для размещения сквозных и интеграционных тестов аппарата, а также общих тестовых оснасток (harness), вспомогательных стабов и утилит, переиспользуемых между подсистемами.

---

## 1. Структура директории

```
tests/
├── helpers/                   # Общие тестовые оснастки и утилиты
│   └── ProxyChannelStub.js    # In-memory стаб канала обмена ProxyChannel
├── integration/               # (План) Интеграционные и сквозные сценарии взаимодействия секций
└── README.md                  # Описание тестового окружения
```

* **`helpers/`** — независимые вспомогательные модули для тестирования (эмуляторы шин данных, генераторы моковых данных, утилиты логирования и кастомные ассерты).
* **Интеграционные тесты** — проверка взаимодействия нескольких секций (например, одновременная работа спиральной секции, постамата и `srvStatesController`). Unit-тесты конкретных сервисов по-прежнему располагаются рядом с их модулями (например, `js/srvSpiralSection/test/`).

## 2. Тестовая оснастка: `ProxyChannelStub`

Файл [`tests/helpers/ProxyChannelStub.js`](file:///S:/nikita.umnov/Project-27_2025-N1-SOFT/tests/helpers/ProxyChannelStub.js).

### Зачем был создан
В рабочей среде все подсистемы АСУ обмениваются данными и командами через брокер MQTT и потоки Node-RED, обернутые в интерфейс `ProxyChannel`. 
Ранее тестирование опиралось на тяжелый внешний эмулятор с реальными MQTT-клиентами, что делало тесты медленными, недетерминированными и уязвимыми к сетевым таймаутам.

`ProxyChannelStub` создан как легковесная, полностью автономная **in-memory реализация `ProxyChannel`**, которая:
1. **Изолирует тестируемый код** от сетевой инфраструктуры, брокера MQTT и Node-RED.
2. **Делает тесты мгновенными и детерминированными**, устраняя сетевые задержки и гонки потоков.
3. **Позволяет контролировать и проверять любые взаимодействия** управляющих контроллеров с каналами датчиков и приводов.

### Краткий функционал
* **Контракт `TypeProxyCh`:** Полная поддержка методов `GetValue(channel)`, `SetValue(channel, value)` и событийной шины `Events.on('${channel}-value', ...)`.
* **Инъекция данных (Data Injection):**
  * `seed({ [channel]: value })` — массовая предустановка начальных значений каналов без генерации событий.
  * `inject(channel, value, { emit })` — точечная установка значения с опциональным эмитом события изменения.
  * `emitChannelValue(channel, value)` — эмуляция входящего асинхронного события изменения канала.
* **Перехват и реакция (Hooks):**
  * `onSet(channel, handler)` — подписка на запись в канал для мгновенной реакции эмулятора (например, включение мотора по команде контроллера).
  * `mockGetter(channel, fn)` — переопределение логики чтения канала.
* **Шпионаж и инспекция (Spy / Assertion):**
  * `callsOf(channel)` — получение списка всех записей в канал с переданными аргументами и временными метками.
  * `lastValueOf(channel)` — последнее записанное значение.
  * `assertSet(channel, expectedValue)` — встроенная быстрая проверка записи в канал.
  * `reset()` — очистка значений, истории вызовов и хуков перед следующим тестом.
