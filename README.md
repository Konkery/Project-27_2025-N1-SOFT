Алгоритм работы:
```js
1. Инициация процесса:
    Получена команда на выполнение транзакции.
    Обработка ячеек заказа по очереди.
2. Проверка доступности ячейки:
        Если ячейка доступна: Включение освещения данной ячейки;
        Иначе: попускаем данную ячейку. Формирует ответ FAIL.

3. Запуск таймаута на включения предупреждающего освещения ячейки (мигающий красный).

4. Проверка тока. Задержка между каждым шагом - 100 мс:
    Замыкание нижнего порта ячейки.
    Замыкание верхнего порта ячейки.
    Размыкание нижнего порта ячейки.
    Размыкание Верхнего порта ячейки.
    Если на каком-то шаге ток не находится в допустимы значениях - отправить сообщение FAIL.

4. Отправка сообщения SUCCESS о выдаче из данной ячейки.

5. Открытие следующей ячейки в заказе.
```

## Матрица
Для демонстрации доступны 3 строки по 5 столбцов. Функционируют все ячейки за исключнием следующих аномалий:
- при открытии ячейки <mark style="background-color: #28a343">04</mark> также открывается ячейка <mark style="background-color: #28a343">09</mark>;
- при открытии ячейки <mark style="background-color: #28a343">09</mark> также открывается ячейки <mark style="background-color: #28a343">14</mark>;
- при открытии ячейки <mark style="background-color: #28a343">14</mark> также открывается ячейки <mark style="background-color: #28a343">09</mark>;
- при открытии ячейки <mark style="background-color: #28a343">05</mark> также открывается ячейки <mark style="background-color: #28a343">15</mark>.
Предполагается серьёзная неисправность в коммутации 4го столбца. Все неисправности корректно обрабатываются в статусах ячеек и подсвечиваются аварийным освещением.

### Реестр каналов
Порты строк (-): ['port1', 'port2', 'port3'];
Порты столбцов (+): ['port4', 'port5', 'port6', 'port7', 'port8'];
Тамперы: ['port1', 'port2', ..., 'port8']; 
Ток: 'nls-04-iout';
Освещение: 'antex-stripe'.

## Освещение
Освещение постоматной секции функционирует без нареканий и корректно реагирует на получаемые команды. В некоторых ячейках из-за особенноствей диодов белый цвет может принимать слегка красноватый и слегка голубоватый оттенки.

Алгоритм работы:
```js
1. Инициация процесса:
    Получена команда на выполнение транзакции.
2. Проверка условий безопасности:
        Если дверь секции открыта: выполнение транзакции запрещается, формируется отказ;
        Иначе: переход к выполнению операции.

3. Инициализация положения лифта:
    Выполнить перемещение лифта вниз до срабатывания нижнего концевого выключателя.
    Выполнить подъем лифта от нижнего положения до первого срабатывания датчика уровня (базовая позиция выдачи).

4. Обработка заказов по уровням:
    Сформировать множество уникальных уровней:
        Levels = Set(orders.level)
        Для каждого уровня level ∈ Levels:
            Переместить лифт на уровень level.
    Выбрать заказы текущего уровня:
        CurrentOrders = orders.filter(o => o.level == level)
        Для каждого заказа o ∈ CurrentOrders:
            Если o.cell.status ≠ OK:
            пропустить заказ;
        Иначе:
            Выполнить выдачу ТМЦ в количестве o.quantity.

5. Завершение цикла выдачи:
    Опустить лифт до нижнего демпфера (тампера).
    Поднять лифт до первого срабатывания датчика уровня.

6. Выдача пользователю:
    Разблокировать замок выдачи.
    Удерживать замок в открытом состоянии в течение 30 секунд.
```

## Лифт
Во всех тестах отработал корректно.

Верхний тампер: 'kcs-41-di-16';

## Матрица
Доступны 2 верхние строки спиралей. Остальные могут быть использованы после перепайки диодов и подключения.
В первый день монтажа и тестов несколько раз наблюдалась ситуация когда спираль завершала работу сразу после начала вращения. В целом тесты прошли успешно.

### Реестр каналов
Управление: 'matrix-ctrl';
Тамперы: ['kcs-41-di-1', ..., 'kcs-41-di-8'];
Ток: 'spiral-current'.
По невнимательности драйвер использует канал-заглушку для мониторинга тока. Следубет заменить 'spiral-current' на 'drs240-iout'. Возможно после этого понадобится скорректировать диапазоны токов в .env.dev файле

## Прочее
Открытие двери блокирует выполнение поступающих команд. Открытие двери в процессе выполнения выдачи не должно повлиять на алгоритм работы.
После завершения транзакции замок лючка удерживается открытым в течении 30 сек. Также в node-red есть узлы OpenBox и CloseBox.
Датчик открытия лючка в классе секции инициализируется но не применяется в алгоритме выдачи.

### Реестр каналов
замок лючка выдачи: 'kcs-41-do-13';
датчик открытия лючка: 'kcs-41-di-12';
датчик открытия двери: 'kcs-41-di-13'.

# Взаимодействие с ВУ
## RFID и QR
Взаимодействие с ВУ по работе с QR/RFID выполняется по следующей схеме:
RFID/QR (ПК ВУ) -http-> Node-RED (СУ) -mqtt-> ПО ВУ
Работа этой схемы была отработана на стенде, но на самом аппарате не тестировалась, поэтому необходимо подключиться к ВУ и убедиться что скрипты отправляют http post запросы именно на 2003 порт НУ.
Скрипты служб перехвата данных от RFID и сканера QR лежат в папке:
/usr/local/bin

## Результаты тестировния
Перед сборкой аппарата для тестирования ВУ использовалась mock-функция класса спиральной секции, которая возвращала ответы об успешности выполнения всех полученных команд.
При тестировании аппарата ВУ направил командыу к 2-м рабочим и 1-й нерабочей строке. По словам разработчика ВУ в ответ он получил 3 ожидаемых ответа (2 успешных и один фейл) а затем еще 3 фейла. При однократном тестировании взаимодействия ВУ с постаматной секцией, были получены ожидаемые ответы.

# Прочее
## Питание
Все ИП, кроме NLS-FrontEnd, запитывающую панель ВУ, имеют мониторящие каналы выходного тока с соответствующими именами: 'nls-01-iout', 'nls-04-iout', 'nls-05-iout', 'drs240-iout'. Все блоки питания работают через свои порты на ICP-DAS. Проблем со считыванием не наблюдалось.

## Температура и влажность
Датчик влажности и температуры DVT-05 делит modbus-шину с контроллером освещения ANTEX. При их параллельном включении освещение постоматной секции перестаёт корректно работать. Было принято решение временно отключить термодатчик, так как освещение более важно для демонстрации работы.
